# fleet-v2: full code review and security analysis

Date: 2026-10-22. Reviewer: Fable 5.1, read-only. Scope: `main` at 8d93854 (worktree clean apart from one untracked planning doc). Nothing was modified, committed or pushed.

Method: the project gates were run locally; six delegated read-only sweeps (shell layer; work-execution; evidence-and-acceptance + operator-coordination; brief-knowledge + onboarding + installation + shared + tooling; cli + mcp + api; web + ui) each read their area in full. Every blocker and every major below was re-read by me against the source; items marked "runtime" were reproduced by a sweep with a scratch script against the built dist or a throwaway repo. Minors are the sweeps' findings, each with a code citation, not all re-read by me.

## Verdict

The codebase is disciplined where it matters most: no shell interpolation, allow-listed subprocess environments, Ed25519 decisions over canonical bytes, a bearer-token API that fails closed when unconfigured, atomic locked JSON stores in most repositories, and a web UI whose twelve mutating buttons all go through the confirmation box. The gates are green on CI.

Four blockers remain, all on the paths that matter most (dispatch, lane diff gate, knowledge shelf), and the dispatch blocker is the same H3 the 2026-10-15 review named. Seventeen majors follow. Several of the 2026-10-15 findings are fixed (API auth S1, ssh host validation S3, grant scope at consumption H7, GET reconcile M9, file locks for most repositories H4); H3, the independence check (H1 in a new shape), the unchecked brief digest (M3) and branch protection (O1) are still open.

## Blockers

B1. `packages/work-execution/src/infrastructure/adapters/ExecutionRunnerAdapter.adapter.ts:41, 824-835` with `bin/ocm-run:127-131, 569`. `startSession` awaits the runner subprocess with a 120 s budget on the assumption that `--detach` makes `ocm-run` return. It does not: `--detach` only disables the abort-on-signal trap, and `ocm_launch` does `wait "$child"` for the whole `opencode run` (tests/ocm-run.test.sh:449-452 proves a detached run blocks until TERM). At 120 s `spawn-run.ts` kills the process group and forces `exitCode: null`; the adapter throws and maps it to `unknown`; `DispatchAttemptUseCase:573-591` saves `reconciling` with `sessionId: null`; `ReconcileAttemptUseCase:78-92` answers `unknown` forever and `StopAttemptUseCase:54-56` refuses without a session id. Every lane longer than two minutes (every real lane) becomes a stuck attempt holding its capacity slot while the server session runs unhandled. Both roots wire this path (`apps/cli/src/composition.ts:950`, `apps/api/server/wiring/work/composition.ts:301`). The adapter test feeds a stdout line (`session started: ses_… (detached)`, `work-execution-adapters.test.ts:882`) the script never prints, so the suite cannot see it. This is H3 of the 2026-10-15 review, unchanged. Fix: create the session through the server API and return its id at once (ocm-run already does `POST /api/session` on v2), or run the dispatcher detached for real and read the id from the server; add one TS test that drives the real `bin/ocm-run` against the fake server.

B2. `packages/work-execution/src/application/use-cases/DispatchAttemptUseCase.use-case.ts:594-611`, `ExecutionRunnerAdapter.adapter.ts:448-450`, `AgyRunnerAdapter.adapter.ts:375-385`, `ReserveExecutionCapacityUseCase.use-case.ts:42-48`. Any `refused` start cancels the attempt and releases its capacity, including the two refusals that mean "a session is live in that worktree": ocm-run exit 75 and the agy dispatcher timeout (whose own message says the lane may still be running). Dispatch never checks the existing attempt's state or unresolved journal intents (`:359, :489-503`; `ActionJournalEntry.isUnresolved` has no caller). Trigger: the stuck attempt from B1, operator re-runs `attempt dispatch`, exit 75, attempt `cancelled`, slot released, lane still running; `cancelled` is not a worktree-claiming state so the busy worktree is reservable again. `work-execution-use-cases.test.ts:1786` asserts this as intended. Contradicts docs/architecture.md: "Unknown state never releases capacity" and "recovery after interruption without duplicate dispatch". Fix: exit 75 and dispatcher timeout map to `unknown`/`blocked`, never `refused`; dispatch refuses when the recorded attempt is in a claiming state.

B3. `scripts/lane-diff-check.sh:84`. The PROTECTED list covers `.github/ .gemini/ .agents/ .agy/ .lane/ bin/ scripts/ AGENTS.md CLAUDE.md GEMINI.md package.json yarn.lock .architecture/ Dockerfile deploy/` but not `.claude/` (Claude Code hooks and settings on the orchestrator's Mac) nor `.opencode/` and `opencode.json*` (opencode permissions and MCP servers for the next lane on the server). Demonstrated (runtime): a lane adding `.claude/settings.json` with a PreToolUse command hook passes with "0 finding(s)", exit 0; the orchestrator then checks the branch out locally. The header's own purpose statement ("a changed agent or permission file changes what the next lane may do") names exactly this class. Fix: add `\.claude/|\.opencode/|opencode\.json` to PROTECTED, and the same to the TS `lane-diff-check.ts` policy if it keeps its own list; add a test case.

B4. `packages/brief-knowledge/src/infrastructure/adapters/KeeperPublicationAdapter.adapter.ts:127-136`. `appendEntryToShelf` does read, push, `writeFile` with no lock and no temp-then-rename, unlike `KnowledgeEntryRepositoryAdapter` in the same package, which uses `withFileLock` and `writeJsonAtomically`. Reproduced (runtime): four concurrent `publishKeeperToShelf` calls on one state dir all returned `published`; `keepers-shelf.json` held one entry. `PublishAcceptedKeeperUseCase` therefore reports published for keepers that are not on the shelf, and a crash mid-write leaves a truncated file after which every later publish fails as unreadable. Default `shelf.provider: local` under the concurrent Nitro API. Fix: reuse the package's lock and atomic write helpers; add a two-writer test.

## Majors

### Shell layer and dispatch scripts

M1. `scripts/lane-diff-check.sh:70`. Changed files come from `ls-files --others --exclude-standard`, which skips ignored paths. `.gitignore` ignores `/.lane/`, `.agents/`, `.env`, `.env.*`, `*.pem`, `/installation/`, so the `.lane/` and `.agents/` entries in PROTECTED can never fire in this repository, and a rewritten `.lane/brief.md` (the file `bin/agy-run:217` feeds to the second-pass implementer in `--mode full`) is invisible to the gate. Demonstrated (runtime): a rewritten brief, a new `.agents/x.json` and a `.env` holding a server password all produce 0 findings. Fix: list ignored files too (`--ignored`) for the protected and secret checks, or refuse when protected ignored paths changed since the recorded tip.

M2. `scripts/ocm-run-hash.txt`. The pin is `3062cbc4…` (the script at 50a422a); `bin/ocm-run` at HEAD hashes to `883b10b3…` (verified). The last three commits changed the script without updating the pin. `packages/onboarding/src/doctor/run-doctor.ts:400-437` compares and emits `runner-binary ocm-run hash FAIL` on every installation at HEAD. No test or CI step checks the ocm-run or agy-run pin (only the bootstrap test does, `tests/fleet-host-bootstrap.test.sh:195-201`). The agy-run pin is current. Fix: update the pin; add a pin check for both scripts to `scripts/test-bin.sh`.

M3. `bin/ocm-run:556-563`. On a v2 server, a failed `POST /api/session` is swallowed (`|| ocm_sresp=''`) and the dispatch proceeds with no `-s` and no `--dir` (stripped at 513-518); the lane runs in the server's cwd and `--status`, `--wait`, `--abort` and the stop trap, all keyed on the directory, never see it. `OCM_DIR` is read only by the test fake (`tests/ocm-run.test.sh:135`), which is why the v2 run test passes through this fallback. Fix: a failed session create is exit 1; add a test for it and one that asserts `-s <id>` on a v2 non-local dispatch.

M4. `bin/agy-run:99, 280`. `--agent` is taken as the next word and appended to agy's argv unchecked, so `--agent --dangerously-skip-permissions` places the refused flag on the argv (demonstrated with a fake agy: exit 0, no refusal). `--model` has exactly this guard at line 192. Whether agy's parser honours it was not verifiable here; by the script's own threat model it is a bypass. Fix: the same dash check as `--model`.

M5. `bin/agy-run:157-168, 213-235`. The lock identifies the lane by bare pid (`kill -0`); `.lane/agy-run.lock` survives a container restart, pids restart low, so `status` reports a dead lane as running and `abort` sends TERM then KILL to whatever process now owns the pid. The lock already stores a start timestamp (line 205) but never compares it to the process. Fix: record and compare the process start time or command line, or hold the lock with an open fd.

M6. `bin/ocm-run:97`. `curl -u "user:$OPENCODE_SERVER_PASSWORD"` puts the server password on argv, visible in `ps` to every local user on every probe, status and abort call, repeated every wait interval. Fix: `--config -` on stdin or a netrc file.

M7. `bin/fleet-host-bootstrap:93`. `chmod 700 -- "$d"` is GNU-only; BSD chmod reads `--` after the mode as an operand and fails (`chmod: --: No such file or directory`, exit 1). The script detects Darwin and lists its tools, then dies before creating any directory. This is why 27 of the bootstrap checks fail on macOS while CI on ubuntu is green; twilight (the macOS verification host) is a target. Introduced by the "-- guards" in e5066ed. Fix: `chmod -- 700 "$d"` (both chmods accept options before the mode).

### work-execution

M8. `packages/work-execution/src/application/use-cases/RequestAttemptAcceptanceUseCase.use-case.ts:41-44, 210-218`. Independence compares the exact id or the id with its first path segment stripped, so `openrouter/poolside/laguna-s-2.1:free` (implementer) versus `openrouter/poolside/laguna-s-2.1` (reviewer) is accepted, as is `nvidia/z-ai/glm-5.3` versus `z-ai/glm-5.3`. Dispatch's own seat-override check uses `underlyingModelFamily` (`packages/evidence-and-acceptance/src/domain/entities/ReviewReceipt.ts:58-72`), which strips `#`, `:` and `@` suffixes and takes the last segment. Tests cover only the exact and first-prefix cases. Fix: one family function used by both.

M9. `DispatchAttemptUseCase.use-case.ts:252-256` with `AttemptArtifactAdapter.adapter.ts:279-281`. The brief is never integrity-checked at dispatch: `request.briefDigest` is stored verbatim and compared to nothing (no consumer after `PrepareBriefPackageUseCase:201-203`). The manifest is read from `request.briefPackagePath`, its `-manifest.json` twin, or the relative `.lane/brief-manifest.json`, through `['cat', path]` with no cwd and no join, so a relative candidate resolves in the orchestrator's cwd (local) or the remote login home (ssh, batch mode ignores cwd). A stray manifest in the operator's checkout becomes the frozen manifest (model, reviewer, owner decision references). `.lane/` is lane-writable and `PrepareFixAttemptUseCase:87` reuses the prior worktree, so a brief edited by the first pass dispatches to the second unnoticed. The 2026-10-15 review's M3. Fix: recompute the digest over the placed files at dispatch and refuse on mismatch; resolve manifest paths under the worktree only.

M10. `AttemptRepositoryAdapter.adapter.ts:94-109`. Saves guard only immutable identity fields; no revision check (contrast `WorkOrderRepositoryAdapter:49-56`). Race: `attempt reconcile` reads `running`, `attempt stop` in another process writes `cancelled` and releases the slot, reconcile writes `running` back. CLI and API share one state dir. Fix: the same revision compare-and-swap as work orders.

### evidence-and-acceptance, operator-coordination

M11. `packages/evidence-and-acceptance/src/application/use-cases/AssessHeadAcceptanceUseCase.use-case.ts:137-151`. `collectFindingBlockers` blocks only findings whose `state === 'unresolved'`, while the aggregate's `unresolvedFindingIds()` (`EvidenceAssessment.ts:222-235`) ignores incoming state and resolves only through recorded dispositions. A review receipt whose findings arrive pre-marked `fixed` or `refuted` (accepted by `ReviewReceipt.ts:93-96` with null reason and evidence; the API route binds only `implementerModel`) is stored as `blocked` yet accepted immediately. Reproduced (runtime): blocked with "finding 'f-1' is unresolved", then `accepted`, 0 dispositions. Fix: acceptance uses the aggregate's blocker list, or incoming states are normalised to `unresolved`.

M12. `packages/operator-coordination/src/infrastructure/adapters/ObservationPublicationAdapter.adapter.ts:49, 74-82, 106-120, 165-169`. Undelivered observations live in an in-memory map; the outbox files written on failure are never read back, and with only `outboxDir` configured a local write is reported `published`. Every CLI command is a new process, so `InspectOutstandingCoordination` never shows the gap. Relays persist their gap on the request; observations do not. Fix: read the outbox directory in `listUndeliveredObservations`.

### brief-knowledge, onboarding

M13. `packages/onboarding/src/doctor/probes-node.ts:277-287` with `sshArgv` at `:157-168`. `['sh','-c','command -v nc']` is sent as `ssh … alias -- sh -c command -v nc`; ssh joins the words and the remote shell re-splits them, so the remote runs `sh -c command` with `-v` and `nc` as positional parameters, and `command` with no operand exits 0 (verified: `sh -c command -v definitely_not_a_tool_xyz` exits 0 locally). Every `command-*` doctor line for an ssh host is a false PASS. The test covers only the local executor. Fix: send `['command','-v',name]` as plain argv, or one quoted remote string.

M14. `packages/brief-knowledge/src/application/use-cases/RecordKnowledgeReuseUseCase.use-case.ts:62-78`. The record is spread by hand and never passed through `KnowledgeEntry.fromRecord`, so `evidenceRef: ''` (or any non-string from the API body, which is spread unchecked) is persisted; every later use case on that entry throws from `fromRecord`. Reproduced (runtime): reuse recorded, then `publishAcceptedKeeper` rejected with "evidenceRef must be null or a non-empty string"; check, decide and supersede fail the same way with no repair path. Fix: validate through the aggregate.

M15. `packages/brief-knowledge/src/application/use-cases/RecordContextSelectionUseCase.use-case.ts:69-71, 85-103`. The selection's `version` is checked for non-blankness only; the entry is loaded but `entry.version` is never compared, and `proposalId` is checked against nothing. Reproduced (runtime): selection at `9.9.9` against an entry at `1.0.0` is recorded with `9.9.9`. The frozen brief's "selected knowledge versions" can name a version that was never checked. Fix: compare and refuse.

### Composition roots

M16. API listen address. `nitropack` binds every interface when neither `NITRO_HOST` nor `HOST` is set; `apps/api/nitro.config.ts` sets neither, the runtime plugin does not refuse, and AGENTS.md does not mention it. The only protection is a bearer token over plain HTTP (the MCP client at `apps/mcp/src/client.ts:8-9` refuses anything but `http://127.0.0.1|localhost|[::1]`). Staging sets `HOST=0.0.0.0` on purpose behind the NetworkPolicy; an operator host running `node apps/api/.output/server/index.mjs` exposes stop, reconcile, forge and knowledge writes to the LAN with a replayable token. Fix: refuse to start, or default to loopback, when the host is unset or non-loopback outside a container.

M17. `apps/cli/src/composition.ts:254-256` versus `apps/api/server/wiring/runtime.ts:373-377`. The CLI names the acceptance assessment `assessment-<attemptId>`; the API's acceptance delegate uses the bare attempt id. Both `readAcceptance` delegates try both spellings, the `assess` path does not, so an attempt verified through the CLI is "Assessment not found" through the API against the same state dir. Fails closed, but breaks the documented CLI and API interchange. Fix: one shared id function.

## What is done well

Subprocess hygiene is consistent: argument arrays, no shell, allow-listed environments built from a fixed list rather than `process.env`, process-group kills with `exitCode: null` on timeout so a killed run can never read as an answer, POSIX quoting over ssh with `--` after the host, absolute `gh` candidates only. The decision kernel is careful (Ed25519 over canonical bytes, strict base64, every field mismatch tested, key file `O_NOFOLLOW` and mode-checked, token scrubbed from errors). The API fails closed when unconfigured, with constant-time token compare, Origin check, JSON-only writes, and caller-supplied facts (implementer seat, doors, clock, worktree path) stripped or compared against the record. The MCP server is read-only against loopback. The web UI routes every mutating button through one well-shaped `AlertBox` and labels post-confirm state as browser-only. Architecture rules hold: no console, no `any`, no Node built-ins in domain or application, no supplier context imports work-execution.
