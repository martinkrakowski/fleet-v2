# Check a hexagen-generated project's architecture as a verification procedure

A project generated by [hexagen-monaco](https://github.com/martinkrakowski/hexagen-monaco) carries two checks of its own. fleet-v2 runs them as ordinary verification procedures; there is no dedicated port yet (hexagen integration plan, D1: procedures first).

| Procedure | Command | What it checks |
|---|---|---|
| `hexagen-arch` | `yarn exec hexagen arch validate` | The architecture rules from `.architecture/manifest.yaml`. It is the same command as the project's `lint:arch` script |
| `hexagen-sync-check` | `yarn exec hexagen sync --check` | Drift: generated files that `hexagen sync` would change |

## Register them

Add both procedures to the installation's `verification.procedures`, as `installation.example/multi-machine/fleet.json` shows:

```json
"hexagen-arch": { "command": "yarn", "args": ["exec", "hexagen", "arch", "validate"] },
"hexagen-sync-check": { "command": "yarn", "args": ["exec", "hexagen", "sync", "--check"] }
```

Then name them in the project's gate procedures (`--gate-procedures hexagen-arch,hexagen-sync-check,…` when you onboard it; see `onboard-a-project.md`).

- **Which binaries run:** the commands run in the lane's worktree on the verifier host, so they use the project's own pinned `@hexagen-monaco/*` binaries.
- **They are not the onboarding probe.** The probe reads files only and never runs project code.

## Reading the result

- **Exit 0** is a pass, unless the procedure declares coverage (see `verification-coverage.md`).
- **Anything else is not a pass,** including exit 2 ("could not run"), a missing binary, a timeout or a killed process. fleet-v2 records the procedure as failed or unknown and never as passed.
- The human-readable output is kept as the receipt's output summary.
- The JSON line of `hexagen-lint --json` is read only for its `filesScanned` count, by a procedure that declares the `hexagen-lint-json` coverage reader. The findings themselves arrive with the `ArchitectureConformancePort` (plan lane F4).

## When hexagen changes

- **Each pin bump is its own pull request.** Use the template at `.github/PULL_REQUEST_TEMPLATE/hexagen-pin-bump.md`.
- **A change fleet-v2 needs from hexagen** goes to hexagen-monaco as a work order against its consumer contract. hexagen-monaco owns that contract.
